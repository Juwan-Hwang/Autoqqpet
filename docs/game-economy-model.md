# QQ 宠物 经济模型与最优调度设计

> 综合来源：用户提供的小红书攻略 + 学园/职业数值表 + 参考仓库 issue #11/#15/#27/#28 + 我们的真机验证。
> 表格数值为**静态参考**（会随版本/年级变），调度器**以实时读取的课程/岗位目录为准**，表格仅用于校验模型形状。

## 1. 游戏机制（关键规则）

### 1.1 三属性与隐藏职业（终极目标）
- 属性：力量 / 智力 / 魅力。
- **偏科**才能解锁隐藏职业（武术家/梦境旅人(造梦师)/大明星）。均衡刷点最亏。
- 解锁公式（经验值）：`目标主属性 ≥ (其余两属性之和) × 2.0~2.4`（≈2.2 可开始"上课抽奖"，2.4 稳）。
  - 属性总量太低时公式不准（碰运气随机属性）；全属性平均 230+ 才好用倍率公式。
  - **越早偏科越省**：反面案例均衡刷高后再偏科，第二/三职业所需属性暴涨（13.7 倍率 vs 2.4 倍率）。
- **疲劳不影响解锁抽奖**：疲劳时一节课属性虽少，但每次上课=一次解锁判定，短课=更多次抽奖。

### 1.2 上课（学分/属性）
- 性价比：**10 分钟短课 > 夏令营 > 30 分钟长课**（3×10m 属性 > 1×30m）。
- 每节课产出：属性加成（按课程主属性）+ 学分；学分攒够**晋升年级**，年级越高单课属性越高。
- **课后"鼓励"(拍手) → 成绩 A/A+，多约 +3 属性**（issue #15，我们 STORY_ENCOURAGE 已实现，仅学习/打工支持）。
- 上课前补满体力/清洁（照顾），否则容易 A+ 失败/属性打折。

### 1.3 赚金币三渠道
- **PK**：~8 秒 50–55 金币 + 心情，**短期暴利、碎片时间首选**（但属好友互动，风控敏感 → 限量）。
- **打工**：稳定长期，**优先短时长岗位**（金币/时间更高，呼应 #27）。
- **冒险**：前期过渡够用。
- **被雇佣**：金币收益只占“基础工资 + 增益加成池”的一部分，**分成分受召回时机支配（见 §1.6）**——放着让它自然结束只拿 10%。

### 1.6 雇佣打工规则（**官方文案，2026-10-14 用户提供**）

两件事分开看：我们当**雇主**（花金币雇友宠代打），和我们当**被雇佣方**（友宠接了我的宠物）。

雇主角：
- 每次打工都可雇佣，**雇佣打工增加额外金币收入**；雇佣不同职业还有**概率给自己属性加点**，职业阶级越高概率越大。
- 双方均消耗体力；**双方都拿到各自的基础工资**。
- 雇主提前结束打工 → **给被雇佣方返还等进度的基础工资**（所以提前收不会害朋友亏钱）。
- **每天 5:00 刷新“雇佣金币加成比例”**，按职业阶级随机取值：阶级越高今日额外金币越多 → 选雇佣职业要看着当天的比例。

被雇佣方的分成表（**只有金币收益，不给工分**）：

| 召回时进度 | 基础工资 | 增益部分分成 |
| --- | --- | --- |
| 0~10% | 0% | 0% |
| 11~40% | 25% | 25% |
| 41~70% | 60% | 50% |
| **71~100%** | **100%** | **75%** |
| **事件结束未召回** | 100% | **10%** |

→ 四个硬结论（推翻了之前的默认做法）：
1. **`RECALL_AT_PROGRESS=0.71` 不是经验值而是官方边界**（一过 71% 就从 60%/50% 跳成 100%/75%）。
2. **自然到期是最差选项**：同样一张 4h 单子，在 71~100% 区间召回拿 75% 增益，放着不管只有 10% —— 差 65 个百分点。
   所以“提前召回”应该是**默认开**，而不是现在这样当“未验证功能”默认关（包形已于 19:17:51 抓包实锤：`0x9760_1 f2=6000`）。
3. 台账口径：被雇佣任务**只计金币**，不给工分。已核：我们的工分只用于岗位**目录的 rate 大小比较**（`AutoRunner` 里 `jobRate`/paypeak），不拿它给被雇佣任务记账 → 这一条没做错的。
4. **另有一个我们还没建模的成本**：宠物被雇佣走就是整整几个小时不可用（通常是 4h 长单）——机会成本。所以“要不要让宠物被雇”与“何时召回”应该一起算：召回到 71% 拿 75% 增益，同时把宠物时间拿回来干别的。

### 1.7 雇佣的实测数字（2026-10-15 00:14，雇主侧）
- 同一张「练习室加练」10 分钟岗位：**不雇佣 ≈ 40 金币**（16773→16818 那笔刨掉福袋 5），**雇佣 = 91 金币 + 工分 10**（直接读自 `0x9874`/`0x9760` 的结算回包）。再扣 **250 金币雇佣费** → 短时长岗位雇佣不划算（91-40=+51 收益 vs -250 成本）；**只有长时长岗位（如 2h/4h）才回本**，算账要按“同一时长不雇佣能拿多少”做基线。
- **服务器把雇佣写在故事名里**：结算回包 `.4.1.7 = “练习室加练（雇佣）”` → 这比 `state=51`/`6500_` 前缀可靠得多，是“这条任务是不是雇来的”的正确判据（之前一致找不到区分方法）。
- 到期时人在页面上的真实发包是**三发 `0x9760`**：到点前 3s `{action=6000,f4=1}` → 到点 `{1000,0}` → 紧接 `{6000,0}`，然后才是 `0x9874`（结算页）+ `0x975b`（收尾）；人不在页面时三发都不出现，但奖励照样到账。
- **订正（2026-10-19）**：本节“再扣 250 金币雇佣费”的归属是错的——**雇佣打工本身不收费**。那笔 −250 发生在 PK 新请保镖的流程里，是保镖的一次性费用，与雇人打工无关（见 §1.8 订正）。上面“+51 收益 vs −250 成本、短岗不划算”的结论随之作废：雇人的增益就是实打实的增益，不再拿它减 250。

### 1.8 雇佣费与 PK 的补充实测（2026-10-15 02:19–02:38）
- **250 金币只在“建立雇佣”时扣一次**：用昨晚已建立的雇佣再打一局 PK 余额 +54 没扣；新雇一人那局 -250+52。
- **主动取消雇佣（0x9bb3）不退款**：取消前后余额不变 → 250 是沉没成本。v2.0.0 的做法：当天已建立的雇佣直接复用；新雇只在
  `岗位分钟 × 每分钟增益（初值 5.1 = (91−40)/10）≥ 250` 时才雇（约 49 分钟以上的长单）。
- **订正（2026-10-19）**：回看当晚记录，“新雇一人那局 −250+52”扣的 250 其实是 **PK 请保镖的一次性费用**，不是雇佣打工的费用——**雇佣打工不收费**（用户真机复核确认；同类参考实现雇人时也不计任何成本，互证）。本节前两条把这笔钱记在雇佣头上是归属错误，原文保留备查、结论以本注为准。自 v2.0.1 起：雇人判断不再有回本门槛（短工照常雇），只看开关、金币留底与每日次数上限；“取消不退款”一条随费用本身一并作废（没有这笔钱）。我们没有自动请保镖的功能，保镖费只在此写明归属、不建模。
- **PK 胜负只看结算称号**（大获全胜/惜败）：输局仍给 15 金币、心情 -1，所以“金币增加 = 赢”是错的。
- 被雇召回回包直接带到账金币（实测 47，与余额差分毫不差），“未获得完整收益”是提前召回的正常提示。

### 1.4 疲劳红线（收益折扣）
- 单日「学习+打工」累计时长：`0–8h ×100%`、`8–12h ×25%`、`12–24h ×10%`。
- 补给（食物/洗护）价格**不随疲劳降** → 10% 档打工**净效率≈7.1%**（#11），可能亏本（#28）。
- 冒险/PK 不计入该疲劳时长（旁路）。

## 2. 优化目标（数学建模）

**决策变量**：每个时间步选择动作 ∈ {上课(哪门课/哪个属性), 打工(哪个岗位), 冒险, PK, 喂食, 洗澡, 空闲}。

**状态**：`S = (t_fatigue, G, P, C, 力量, 智力, 魅力, 学分, 年级, 阶段)`。

**目标（字典序，需用户确认主属性）**：
1. 最大化**目标主属性**（偏科，逼近 `≥ 2.4×(其余两属性之和)` 解锁隐藏职业）；
2. 其次最小化达到该目标所需**真实时间**（优先短课/高属性每时间）；
3. 约束：全天金币 `G≥0`（不透支）且 `G_end ≥ G_start - 预留职业升级金`（自给，#11）；
4. 约束：每步动作前 P/C 达准入；补给整数件、P/C 封顶 100（防溢出浪费）；
5. 疲劳：动作收益按 `q(t_fatigue)` 分段积分（跨档分段）。

**关键子策略**：
- 上课永远选**目标属性**、**最短时长**、当前年级属性最高的课；课后必**鼓励**(A+)。
- 金币来源优先级：PK(高ROI但限量/风控) > 打工短任务 > 冒险；金币低于安全线时先打工/PK 赚学费。
- **亏本保护**（#28）：某动作 `净收益 ≤ 0`（当前疲劳档）则不做。
- 疲劳窗口宝贵：前 8h 尽量排**高属性效率的学习**；8h 后若纯为"解锁抽奖"可继续廉价短课，否则转打工/收工。

## 3. 数据来源（全部走已验证的实时只读命令）

### 3.1 课程字符串自带完整经济数据（实测 9.3.65）
`SCENE_CATALOG(0x9ab2, f1=6100)` 每门课的 cost/duration/reward 是 **markdown 串**，含全部所需参数：
```
cost  = '![..icon..] 22(当前..4918)，体力5(当前90)，清洁2(当前96)'
         → 学费22、当前金币4918、体力消耗5(当前90)、清洁消耗2(当前96)
duration = '10分钟' / '30分钟'
reward = '力量+8[ ](mqqapi://..petTips..text=<URLenc 提示>)'   → 取 '[' 前部分: 力量+8 / 智力+8 / 魅力+8 / 随机属性+20
```
解析正则：`(力量|智力|魅力)\+\d+`、`体力(\d+)`、`清洁(\d+)`、学费=cost 中首个 `\d+`、时长 `(\d+)分钟`。
实测样例：初级 10m课=学费22/体力5/清洁2/属性+8；30m课=学费66/体力15/清洁6/属性+20；萌芽夏令营=30m/随机属性+20。
→ **短课属性/时间更高(48/h vs 40/h)，学费按时间持平 → 短课优先（与攻略一致）**。

### 3.2 三属性总量
实测**不走标准 OIDB**（GetUserPet/OWN_PROFILE/DISPLAY/0x994b/0x945a/0x9959 均无 78/53/66），疑客户端缓存。
→ 优化器核心决策**不需总量**（只需每课属性增量，已可实时读）；解锁/选属性用**用户给定基准 + reward 累加**追踪，后续可 IDA 补精。

## 5. 实现顺序
1. 先补**属性/学分/年级**的读取与课程 reward/cost 字符串解析（喂模型的数据层）。
2. `DayPlanner`：把上面目标写成 DP/贪心+lookahead，输出下一动作。
3. 接 AlarmManager 调度器：每完成一步→重读→重规划。
4. 用攻略表格数值做**单测**校验模型（如短课效率、疲劳净收益）。
