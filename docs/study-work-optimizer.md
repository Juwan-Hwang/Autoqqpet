# 学习—打工—补给 联合最优调度（设计）

> 模型来源：qq-pet-copilot Issue #11（作者 yikehuang，2026 提出，含精确求解）。
> 原文见 `_issue11_body.md`。本文件是**为 Autoqqpet 落地重述 + 数据接线 + 现实修正**。

## 1. 模型骨架

状态 `S = (t, G, P, C)`：t=当日累计"学习+打工"活动分钟；G=金币；P=体力；C=清洁。
动作：学习 / 打工 / 喂食(饼干·虾仁) / 洗澡(香皂·沐浴球)。

疲劳倍率（学习、打工收益共用的时间轴，按**实际占用分钟分段积分**，跨档不整任务套单一倍率）：
```
q(t) = 1      , 0   ≤ t < 480     (0–8h)
       = 0.25  , 480 ≤ t < 720     (8–12h)
       = 0.10  , 720 ≤ t ≤ 1440    (12–24h)
```
目标（字典序）：① 最大化疲劳折算后的学习收益；② 相同时完成更多课程；③ 再相同时最大化期末金币、且学习尽量排在早的高倍率时段。
约束：`G_k ≥ 0`（每步不透支）、`G_end ≥ G_start`（当天自给）、`t_end ≤ 1440`；每个动作前 P、C 需满足准入门槛；补给按整数件。

## 2. 可直接推导的结论（指导实现，不硬编码数值）

- 补给**单位恢复成本**：饼干 0.5/体力、虾仁 1.0；香皂 0.2/清洁、沐浴球 0.6。
  → **饼干严格优于虾仁、香皂严格优于沐浴球**；理想最优解里虾仁/沐浴球用量为 0。
- 一节课长期可持续成本 = 学费 + 体力×0.5 + 清洁×0.2（示例 70+5+0.8 = **75.8**）。
- 一次打工补给成本 = 体力×0.5 + 清洁×0.2（示例 2+0.4 = **2.4**）。
- 10% 档打工**净效率≈7.1%**（不是 10%），因补给价格是固定的、不随疲劳降。
  → **前 8 小时的满收益窗口是最稀缺资源**；不能"先学满再打工"，要在高收益窗口内**穿插打工**赚学费。
- **亏本保护（issue #28）是本模型的特例**：某岗位在当前档 `收入×q − 补给成本 ≤ 0` 时，优化器自然不选它。

## 4. 实现形态（对齐 issue #5 维护者诉求：可选策略 + 引导式默认）

- 作为一个**可开关的"数学优化"策略**，不硬编码"18 学 102 工"。
- 每轮：读实时参数 → 求解 → 输出**下一个动作** → 执行并复查 → 重新规划（滚动式）。
- 求解器：状态按分钟离散 + Pareto 支配剪枝的动态规划/搜索；或先做"金币守恒下的贪心穿插"近似，够稳再升级。
- 对服务器 25%/10% 档的小数结算提供**取整方式配置**，避免累计误差。

## 5. 现实修正（issue #11 理想化假设里不成立、要补的）

1. **体力/清洁上限 100 → 溢出浪费**：模型忽略溢出，实际喂超了浪费，需求解时对 P/C 封顶。
2. **准入门槛**：打工/学习可能要求 P、C ≥ 某阈值才能开工，动作前判断。
3. **每节课属性收益 X 不等**（不同科目/力量智力魅力、不同阶段），"完成更多课程"≠"收益最大"，目标①应按真实 X 加权。
4. **岗位收入随职业/等级变化**，且长时任务(2h/4h)读数在活跃>8h后是**已衰减显示值**（#27 坑）→ 采集时机要么在早档、要么次日刷新后采全量。
5. **要预留职业升级金币**（#11 维护者补充：后期职业升级耗金大）→ 加一条 `G 下限 ≥ careerReserve` 约束。
6. **护理勋章**不能用一键（API 喂食相当于"一键"）→ 想要勋章的用户提供"仅读取不代练护理"选项。
7. **好友互动(踩踩/访问/PK/雇佣)不进此优化器**：那是风控敏感项（#19），单独低频+上限。

## 6. MVP 落地顺序

1. 先做 `OptimizerParams`（从上面命令读一组实时参数）+ `DayPlanner.plan(params) -> List<Action>`（先用贪心：高倍率窗口内"打工1+学习1"穿插，金币触及 careerReserve 则纯学习，`净收益≤0` 停打工）。
2. 接入 t11 调度器：每完成一个任务→重读状态→重规划→执行下一动作。
3. 升级为带 Pareto 剪枝的 DP 精确解 + 单测（拿 issue #11 那组参数复算，应得 17.1X、最终金币≈707 对齐）。
